## Findings

- **Confirmed credential in reachable history:** `.screener_csrf` contains 32 nonempty bytes in `e71d1ee168d4a2b5c155aa6302347aeaad841e46`; that commit is an ancestor of current HEAD. HEAD's removal does not remove exposure. Value and credential hash are deliberately omitted. Treat as exposed; invalidate/renew the associated credentials in a coordinated future maintenance operation. Rotation alone does not make the present branch a clean publication lineage.
- Reachable-object heuristic scan covered **25,830 objects /25,428 blobs /13,667,407,032 blob bytes** across local refs. Six pattern candidates are URL-credential patterns in downloader/permit tests and retained test patches, not six newly confirmed production credentials. Compressed archives were scanned as raw bytes, **not unpacked**; unknown formats/entropy-only secrets remain a gap. No installed gitleaks/trufflehog was found. The supplemental scan checked 26,202 exact-index/local-source texts (including untracked source), with59 texts over8MiB skipped. Its eight candidate occurrences refer to five synthetic URL-credential rejection tests/patches; `secret-candidate-review.json` records their test definitions without values. No additional production credential was confirmed by these heuristics. See `source-secret-scan.json`; this is not archive/layer clearance.
- **Oversized history:** four blobs exceed100MiB: A0 artifact coverage JSON, two extracted-document JSON payloads and the historical B2 backup export (854,143,584 bytes). There are additional50–100MiB extraction blobs. `git-safety.json` lists exact paths/OIDs/sizes. These exist in reachable history regardless of later ignoring/untracking. The current index also contains two approximately694MB OCI tar archives and many historical harness TAR files exceeding100MiB. `large-files.json` lists local/index state. This audit does not rely on a fresh remote policy check: such bulk is independently disallowed by this source-only manifest.
- `.gitignore` correctly excludes OLD, host store/database/SQLite sidecars, `.env*`, Screener secrets, many runtime/experiment outputs and common archives. **Tracked exceptions remain**, including PDFs, log/evidence trees and staged OCI/TAR archives. No database is indexed under the usual `.db`/`.sqlite` names, but extensionless embedded databases and databases inside archives are not thereby cleared. Root and scrapper ignore rules differ; test fixture publication must be explicit.
- **Machine-specific configuration:**410 indexed local text files contain `/Users/`, `/Volumes/` or `/private/tmp/` paths. These include evidence and required runtime configurations, not necessarily credentials. Current plist, activation adapters, source-mount overlays and sentinels are tied to this host/drive. Parameterization for distribution is future work; do not edit sealed production identities during a Git cleanup.
- Docker secrets are mounted via `SCREENER_SESSION_FILE`/`.screener_session`, not intentionally embedded by the root Dockerfile. `.dockerignore` restricts context to scrapper and excludes store/auth files. Root Compose contains unprofiled legacy workers and old release-config references; a clone must not use broad `docker compose up` as a reproducibility check. The Dockerfile healthcheck opens SQLite without `mode=ro`; do not use it as a read-only audit probe. Do not infer secret-free image layers from Dockerfile intent; retained OCI archives were not layer-unpacked/scanned here.
- No project-root LICENSE/NOTICE was found by repository file search. Ownership/licensing of original code, fixtures, exchange/Screener captures, publisher documents, screenshots, fonts, vendored binaries and model outputs must be established before redistribution. BSE access/reuse attestation is acquisition evidence, **not general redistribution clearance**. Private visibility does not settle those rights. No legal conclusion or new publisher access is asserted.
