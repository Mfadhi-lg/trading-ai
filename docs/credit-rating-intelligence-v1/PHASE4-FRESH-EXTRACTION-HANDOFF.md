# Phase 4 — minimal fresh-document extraction handoff

The extraction, evidence and export pieces exist. The missing connection is a document-driven candidate producer and intake branch: `build_record` currently requires a source-review file, inventory and saved chat responses, and atomic proposals require a retained parent. It cannot currently take an arbitrary model's atomic JSON directly. No inference was implemented or run in Phase 3.

1. **PDF to canonical source (exists).** Hash original bytes, create `DocumentContext`, and call `offline.extract_local(body, '.pdf', ocr=False)`. This reuses `documents.pdf.extract_pdf` and D03 canonical pages/elements/tables with parser provenance. Persist the canonical JSON and both its file hash and `evidence.canonical_hash` (these are different hashes). `credit_v1.build_record` already supports extraction when `canonical` is omitted, checks PDF page count and source identity, and extracts deterministic ratings/liquidity labels. Fresh intake needs a small manifest writer: PDF, canonical, company/document metadata and source receipt. Replace the historical inventory assumption with a local acquisition receipt supplied as input; do not modify acquisition or a database. Report date must be independently sourced, not inferred from an action date. Existing cover validation requires the literal company name/date, so failures need review, not silent aliases or repairs.

2. **Stable regions (enumeration glue missing).** Build a source-only region catalog from the frozen canonical JSON using `text_evidence` for text spans and `cell_evidence` for table cells. Reuse the current locator string from `attach_evidence`: `p{page}:e{element}:r{row}:c{column}:{start}-{end}`. The globally unique identity is `(PDF SHA-256, canonical SHA-256, locator)`, not that locator alone. Supply full page context and table headers beside the addressable spans/cells. Freeze the catalog bytes and parser version before inference. These IDs are stable across replay of one canonical version; a different parser/offset sequence creates a new version and invalidates prior reviews. Do not reuse the old model-invented line IDs. A minimal catalog may enumerate nonempty native lines with their actual canonical offsets plus all table cells, allowing multiple region IDs per proposition.

3. **Proposed atomic generation (missing).** One already available provider receives only the new source catalog, original document identity, V1 field names and atomic JSON contract. Ask for independently dated/scoped propositions with literal units, attribution, statement kind, conditions, qualifications and support region IDs; allow explicit null/unknown. Separate prior-year comparisons and realised facts from assumptions/plans. Save request hash, raw response bytes, provider/model receipt, usage and candidate hash. No benchmark/reference answers, Vimta/EKC packets or manually prepared disclosure packet enter the prompt. Do not run a benchmark/model selection loop. Invalid output remains an intake failure/review item; do not repair its meaning.

4. **Admission (small intake branch missing).** Prefer the existing `replay_candidate` boundary for fresh proposals: map the strict provider DTO to the existing candidate shape, assign stable JSON pointers and reuse its source-specific identity/origin receipt. With no review, this returns NEEDS_REVIEW. Resolve candidate support IDs through the catalog to exact canonical locators and validate them independently. To obtain the finer atom evidence path, make each unreviewed original proposal its own retained parent, then wrap it in the existing atomic packet contract (parent claim ID/hash, PDF/canonical hash, complete atom, support). `derive_claims` needs no new admission policy. Atom support must be resolved by Python, never trusted as model-provided offsets. Preserve originals; any reviewer correction is a derived proposal with separate provenance. Do not manufacture parents from historical companies or fabricate a provider response envelope.

5. **Python evidence checks (exists; resolver glue missing).** Resolve IDs exclusively from the frozen catalog, then use `attach_evidence` / `validate_evidence`: actual page, element or cell, exact offsets/quote, source origin, cell box where applicable and identity hashes. Reject unknown IDs, altered quotes, moved periods, missing headers and partial/unreviewed OCR sources. Packet and whole-atom review hashes already fail closed on changes. Exact-match evidence does not prove semantic entailment, scope, header binding or completeness. Preserve the pinned whole-candidate source-review gate: no automatic SUPPORTED decision merely because a quote matches. Initially fresh candidates remain NEEDS_REVIEW until source review pins each accepted atom; invalid evidence is WITHHELD. First Phase 4 demonstration can automate generation while retaining this review gate.

6. **Missing required fields (exists).** Reuse `FIELD_NAMES`, `coverage_claim_ids`, `field_state` and the ledger assembly. A field without an admitted finding is UNRESOLVED, with pending claim links when available. A supported atom with unknown scope stays component-UNRESOLVED; field coverage stays PARTIAL. No output from a model means neither source absence nor completeness. NOT_DISCLOSED requires explicit absence plus completed source review. Count coverage by field, suppress parent/child duplicate links, and do not sum repeated disclosures.

7. **Exports (exists).** Reuse `validate_record`, `render_markdown` and new-only `export_record` for accepted JSON/report, coverage ledger and review queue. Include proposed candidates with evidence results in the queue. Preserve raw response/request/catalog/source receipts alongside the manifest. Keep the provider invocation outside `offline_guard`: inference is an explicit separate generation command; subsequent admission/replay/export remains offline and database-denied. Record generation usage separately from replay's zero inference calls. Distinguish `generated_ai` provenance from `replayed_ai` and `deterministic_extraction`; the current fixed execution-mode list needs this small metadata update.

8. **Minimal provider adapter code to write next.** Add a focused module, e.g. `credit_candidate_provider.py`, with `build_region_catalog(context, extraction)`, `build_request(context, catalog, fields)`, `generate_candidates(provider, request)`, and `load_candidate_bundle(path, context, extraction)`. The provider is an injected existing callable returning JSON and a receipt; do not add credentials, new models or experiment orchestration. Strictly validate required atom fields/enums, nulls, duplicate IDs, document identity and field membership; resolve support IDs, preserve raw bytes, and pass the resulting candidates to existing admission functions. Add one optional manifest `candidate_bundle` branch in `build_record` alongside saved-response replay, and allow an empty reviewed-claims packet for a new document. Existing `responses` can be empty, but the fresh bundle still needs its intake branch. Small helper extraction of shared ledger/export assembly is optional, not another framework. Existing provider transport code is in `research/general_ai_experiment/runner.py:request`; it is tied to experiment-specific orchestration and should not be invoked through its benchmark CLI. Supply the already available provider at the new adapter boundary rather than import its preparation/cloud workflow.

The next demonstration must use one genuinely new local credit-rating PDF and a new output directory. Generate proposals from source regions automatically, retain invalid/unsupported items, source-review a bounded subset, replay offline twice, and export accepted intelligence plus missing fields and queue. Include tests for unknown regions, quote/identity tampering, comparative periods, scope, funding assumptions, review gating and deterministic saved-response replay. Success is a reproducible new-document path with visible unresolved items, not a target acceptance count. No Phase 4 execution is authorized or started by this handoff.
