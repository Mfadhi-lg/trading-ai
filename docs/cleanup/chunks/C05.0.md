## Implemented contract

`scrapper.runtime_identity` is inert on import and validates resolved writable
targets before directory creation, writable SQLite connection, document-store
probe, output creation, migration, or worker/browser startup.

- Every writer requires an explicit `TRADING_AI_ENV` value of `production`,
  `development`, or `test`.
- Production requires an authorized identity file with exact DB/store/document
  targets and nonempty release, Git commit, and image IDs. Store/document
  sentinels must match the release, role and resolved path. Extra runtime roots
  are individually listed; there is no general bypass flag.
- Development/test reject the known host production tree, external document
  store, container `/data` and `/documents` targets, recognized production
  Docker mount identities, and production sentinels.
- A restored clone containing a copied production marker requires a separate
  destination-bound clone identity with environment, clone ID, exact root and
  marker SHA256.
- Successful checks log resolved targets and public release/Git/image/clone IDs
  without reading or logging credentials.
- Read-only DB connections, imports and help remain inert. A read-only `view
  tables` run succeeded with no environment identity and preserved the complete
  SQLite hash.

The guard is wired into configured directory creation, every writable shared DB
connection, document-store validation, the central CLI's explicit output paths,
current browser host/headed launchers, capacity publication, quarter scripts,
diagnostics, and standalone reporting/campaign mains found by the static audit.
Existing command names, arguments and read-only behavior are retained.

Deliberate behavior change: a writer without a valid environment/target identity
now fails before creating or opening its targets. Production configurations must
provide the identity and sentinels when C05.2 prepares the release. This
candidate is therefore not suitable for activation by itself.
