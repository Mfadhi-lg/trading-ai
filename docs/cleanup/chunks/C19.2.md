Implementation and deliberate changes:
- Migration **069_worker_claim_fencing.sql** adds only nullable `claim_token TEXT` to the three existing queues. Existing rows remain intact with NULL tokens; future claims atomically assign fresh 128-bit random tokens. Attempts can be reset by the existing operator requeue path, so an attempt counter alone cannot prevent generation reuse. All **68** released migration files remain byte-for-byte unchanged. The C04.1 manifest is preserved; the candidate has a new reviewed manifest and default audit path, including explicit preparation/disposable profiles. Migration SHA256 `3207e495e464d079ffd5d18ade9197d5f9cd3510916e83f2dd281f7aec7a71cb`. It was applied only to disposable restored/test clones.
- Generic/direct claim snapshots are read **before commit**. Completion requires job ID, active status, original owner, count and exact token; a stale, wrong-owner or duplicate finish updates zero rows and raises. Internal completion callers now provide their captured token/count. Missing token arguments fail closed; no unsafe inference from the current DB claim. CLI names, flags, outputs and ordinary outcomes remain compatible.
- Browser finish requires run/job/status/owner/count/token. Claim return preserves the legacy PRE-increment count/status, but adds the actual owner/token. Existing transient `<3` policy still leads to **four** claimed invocations, as explicitly verified; accounting correction remains C19.4.
- Browser runtime and bridge sessions have unique owner incarnations. EOF/finally releases only that session, and marks it stopped. Host import/rate-limit/finish messages carry exact tokens and incremented counts. Legacy/unversioned/v1 messages remain usable for a first session claim; repeated claims without a token are ambiguous and refuse. Explicit old/incorrect tokens refuse before import/completion. Protocol version handling and transport selection remain compatible.
- Browser persistence/rendering keeps its previous short transactions. A separate short `BEGIN IMMEDIATE` verifies the captured browser claim before cross-queue reconciliation. Stale work cannot reconcile newer queues. Network/render/OCR is outside this write transaction. Immutable late content/download evidence may already be saved before ownership is lost; it is retained honestly, without allowing stale completion/reconciliation. Existing content processing/extraction ownership is not changed.
