## Selected behavior and compatibility

A2's migration protection is superseded by C04.2's stronger default compatibility
check on every DB path. Its automatic custom-test bootstrap and additional
`init-db --apply-migrations` requirement were not adopted; the current explicit
`init-db --db PATH` interface remains. Publisher-policy code already matches
A2 and is retained. Compose changes belong to C05 and were not selected.

Selected A2 fragments add typed BSE HTTP 403 handling, durable per-dataset access
holds, scheduler hold/status reporting and explicit evidence-bearing resume.
A hold survives retry rungs and later days, preserves accepted snapshots,
watermarks and queue records, and does not suppress unrelated NSE work.
404/nonpublication and transient failures remain distinct and retryable.
`exchange-scheduler --resume-access BSE_DATASET --resume-evidence TEXT` releases
only a named active hold; it performs no fetch or checkpoint/queue change and
rejects combination with scheduler execution. Status connections are read-only.

The rebase retains current standalone defaults, period coverage/backfill,
accepted-quarter checks, browser recovery/validation/identity and host lifecycle.
It does not overwrite current modules with copied A2 files. An initial selected
hunk accidentally included A2's stale removal of an accepted-quarter local;
the full regression exposed it and it was removed before final validation.
A2's primary-to-revision hold gap was also closed: a newly blocked dataset is
excluded from the same attempt's revision sweep. A focused test covers this
alongside an unrelated retryable NSE failure.

Deliberate changes: confirmed BSE 403 now creates an access hold instead of
repeated automated requests; status distinguishes access denial from missing
publication; explicit operator resume is available. Browser/publisher policy
is unchanged. Scheduler contract tests cover these changes; C19 queue fencing,
H07 races and general cross-host coordination are not claimed here.
