Implementation and deliberate behavior changes:
- Active generic/direct/browser acquisition work renews its captured owner/token/count with a job-scoped private connection and thread at TTL/3. Defaults retain 600/600/900-second leases. Synchronous checks before persistence/completion verify and extend ownership. Only expiry changes; count, attempt history and updated timestamps do not. Expired/replaced/nonactive claims cannot renew. Renewal failure raises OwnershipLost and refuses completion instead of creating WORKER_EXCEPTION retries. Threads stop/join at context exit; bridge completion/release/EOF stops only its own renewal. Native/host browser transport, pacing, cleanup and protocol versions remain compatible. The command injects renewal into the bridge, preserving its dependency boundary and direct-library compatibility default.
- Migration **070_document_extraction_claims.sql** adds one small resource ownership table, initially empty. No existing table/row/column is rewritten, and all **69** prior migration files remain unchanged. Exact content/parser/version/OCR/version/options form the resource key. A short claim transaction refuses an active competitor and gives each released/expired resource a fresh owner/token. Claims are retained as current ACTIVE/RELEASED resource state, not a new work queue or immutable attempt ledger. Migration SHA256 `cc6c82616d2e78d622a4e925c8b8bf7f9916c9b4b585a0ae9663f7541e7e447b`; reviewed manifest retains prior identities and adds explicit preparation/disposable profiles. It was applied only to disposable fixtures.
- Deterministic extraction runs outside a write transaction. Inside BEGIN IMMEDIATE, persistence verifies the exact cache key and unexpired captured token/owner, then saves extraction/pages/validations/preferences and releases its claim atomically. A stale parser produces no extraction/export; finally releases only its own generation. Crash leaves the claim recoverable through expiry. Ordinary parser failures and cache hits retain their prior output semantics; different OCR versions/options retain independent outputs. Existing direct persistence callers retain their compatible optional-claim API; actual extraction orchestration supplies the fence.
- Busy/lost extraction ownership does not permanently mark browser processing FAILED. It keeps evidence eligible, waits cooperatively in follow mode, and returns in finite mode. Broader normalization/handoff and whole browser processing-job ownership remain C21.
