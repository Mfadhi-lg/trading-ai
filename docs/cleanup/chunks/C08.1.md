## Implemented compatibility and ownership

The [path contract](../runtime-paths.md) specifies each setting and owner.
`SCRAPER_STORE_PATH`, `SCRAPER_DB_PATH` and `SCRAPER_DOCUMENT_STORE_PATH` retain
their exact behavior; all existing constants/imports and default children remain
compatible. `RUNTIME_ROOT` aliases `STORE`; `DOCUMENTS` aliases
`DOCUMENT_STORE`; `DATABASE_DIR` identifies the DB's existing parent.

Files, snapshots and exports gain optional independent settings. Campaigns,
logs, browser state and backups gain explicit configured locations without
creating directories or switching their existing script/host consumers. New
locations default below `STORE`. `ensure_dirs()` creates only its existing
directory set at the selected roots. DB/WAL placement, document `artifact_content`
children, MF import paths and package migration ownership remain unchanged.
Existing `/data` and external `/documents` settings retain their layout. No
stored `local_path` row or physical content location is rewritten.

H03 now receives every configured root, including the new roots, before
directory creation or other existing guarded writer entry points. Resolved
production aliases/mounts/copied markers remain protected. Production roots
outside authorized store/document locations require exact
`additional_writable_roots`; no bypass is introduced. External content sentinel,
reserve, host capacity-file preference and staleness behavior are unchanged.

Deliberate behavior extension: explicitly configured split roots are routed to
their existing children and are identity-checked. An unauthorized split root
fails before any directory is created, including when another writer invokes
the shared configuration guard. Imports/help remain inert. Default configured
roots pass existing release identity rules without editing production manifests.
