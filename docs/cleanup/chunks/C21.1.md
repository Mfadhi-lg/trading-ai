The migration adds a durable inbox, versioned extraction work and an INSERT trigger. Content and its inbox handoff commit or roll back together across download/browser/derivative registration paths. All saved origins/media remain evidence; supported PDF/PPT/PPTX and credit-rating HTML become extraction work only through explicit bounded reconciliation. No existing content is scanned/backfilled by migration. No worker, campaign, CLI, Compose, normalization record or source processing behavior is changed. Unsupported audio/video stays in the inbox for later explicit ownership; this subchunk does not queue or implement normalization/transcription.

Reconciliation requires 1–100 selected IDs and explicit parser name/version, OCR engine/version and canonical options. It idempotently recovers missing historic handoffs and links only the exact extraction cache identity. `extraction_id IS NULL` means pending work; a recorded extraction retains its actual failed/unknown/usable outcome. Creating work never validates an artifact or changes preferred content, origin, financial acceptance, retries or availability. A changed processing version creates separate pending work only when explicitly selected; no full-corpus re-extraction.

Work claims reuse C19.3's extraction resource key and fenced lease, including its renewal and parser-persistence transaction. Legacy/new workers cannot own that same resource concurrently. Consumers must pass the captured claim to existing `persist_extraction`, renew through existing renewal helpers, then reconcile the exact cache version. C21.2 will wire the consumer; existing `extract_document` cannot simply be called while holding a second claim. A crash before version enqueue leaves the inbox recoverable; a crash after extraction persistence leaves the exact cache recoverable; expiry/reclaim fences stale persistence. No database write transaction spans OCR/network work.
