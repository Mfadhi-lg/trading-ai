Shared browser mode requires Linux, explicitly applied migration 071 and a trusted `OperatorAuthorization` receipt matching the finite run and selected exact hosts. The ordinary `--operator-authorized` boolean does not manufacture a receipt. Bridge setup verifies schema/receipt before claims, and the host verifies the matching receipt and bounded wall-clock skew before browser launch. Expiry is checked again before subsequent claims. Actual operator receipts are an activation prerequisite, not supplied by this offline chunk.

All allowed HTTP(S) GET/POST navigation, redirects, forms, scripts and download requests use the C20.2 killable HTTP child and a fenced cross-queue publisher-group permit. A browser route is fulfilled from the bounded child response; it never calls `continue_` or `route.fetch`. Redirects return to the browser for fresh interception, while direct-PDF/viewer requests use explicit metered per-hop redirects rather than APIRequestContext. Service workers are blocked, intercepted WebSockets close without connecting, and unsupported methods abort. Existing image/font/media suppression and static CRISIL/Brickwork document-only filtering remain intact. Shared mode uses a fresh context per job so an old page cannot issue requests against a new claim. HTTP cookie-jar values are installed explicitly into the browser; viewer requests read browser cookies, including JavaScript-set session cookies. Original response bytes and generated DOM/PDF captures remain distinguishable under existing canonical persistence and validation.

Queue ownership is checked before dispatch and while waiting/streaming; no DB write transaction spans I/O. Each permit can dispatch once. The child has an independent absolute monotonic deadline capped below permit/receipt expiry, Linux parent-death fencing and kill/join cancellation before capacity release. Queue completion/defer refuses active requests. Bridge EOF/crash does not eagerly release request capacity while an external child might still be finishing; finite child deadlines and durable permit expiry bound recovery. Existing queue renewals, publisher cooldown imports and fenced crash/reclaim behavior remain in force.

Short shared pacing waits retain the claim; long waits or unapproved hosts defer RUNNING → PENDING with an existing run/host wait deadline. A fenced pre-dispatch defer refunds exactly this claim's increment and creates no fabricated download/content attempt. After real dispatch, the invocation remains spent and completed URLs/statuses/redirect locations remain in administrative evidence. Stale owner/token/count/expired leases cannot refund newer work. Shared cooldowns retain conservative 24-hour 401/403 and six-hour 429 defaults, honor longer Retry-After, persist the three-failure circuit and never clear unrelated future deadlines on success.
