# C01.3 — H05 offline lifecycle design

Status: **DESIGN COMPLETE; H05 EXECUTION NOT STARTED**. Implementation belongs to
separately selected C02.3. This design authorizes no live source requests, schema
work, production maintenance, or full-corpus processing.

## Common harness and replay contract

Use production entry points with fake transport at their existing injection
seams, never a second implementation of ingestion/recovery. Network must be
disabled at the container boundary and unexpected URLs must fail immediately.
Use the pinned Python 3.12.14 image recorded in C01.3, read-only source/fixtures,
no production volumes/socket/secrets, and disposable SQLite/store/output roots.
Reconstruct the dirty baseline, not just its Git commit. Current fixture/source
hashes are in `../baselines/C01.3/fixtures.json` and `dependencies.json`.

For fixture-built tests, create one isolated migrated SQLite fixture baseline,
check integrity and foreign keys, freeze its full-filename migration manifest,
then make independent old/new copies with writers disabled. A restored production
clone, if needed, requires C02.1/C02.2 proof and explicit isolated identity. Do not
renumber either `065_*` migration or migrate production to run these tests.

Use a fixed UTC clock with T0 initial result, T1 revised result, T2 still-missing
document, and T3 late publication. Select dates consistent with the fixture's
actual June 2026 quarter. Record all injected times in the expected output;
verify first-observed, fetched, publication, acceptance, due/attempt and completion
times independently. Patch module-local `utc_now` references where APIs do not
accept clocks; accepted timestamps must not retain wall-clock time. Use fixed
worker IDs, deterministic UUID/claim tokens and fake monotonic/sleep hooks.
Failures to freeze a time/ID must be fixed in test setup, not blanket-excluded.

Old/new runs use identical response bytes, ordered fake requests, clock steps,
options, policy and parser/OCR versions. Serialize ordered rows with explicit
columns, JSON key order, null handling and units. Compare IDs directly when seeded
identically; any necessary remapping must name exact foreign-key relationships.
Only replace the known sandbox-root prefix in paths. Do not discard entire
tables, attempts, timestamps, source references or provenance to obtain equality.
H02 serialization/fingerprints are C02.2 work, not implemented here.

Observe companies/security identifiers, response blobs/fetches/parses/raw fields
and cells, financial observations, accepted page versions/acceptance events,
artifact events/expectations/check events, sources/contents, queue attempts and
recovery candidates/attempts/actions, extraction pages/segments and readiness.
Verify stored bytes against recorded SHA256 and reread originals after processing.
Metadata hashes alone do not prove full corpus integrity.

## Flow A — accepted result, immediate and late documents

1. Reuse `test_screener_discovery.screen_html` for a bounded synthetic result
   screen and `screener_discovery.discover_screener_results` with fixture/fetcher
   injection. Assert standalone identity, quarter, candidate and queued work.
   This inline screen is synthetic; freeze a named derivative with hash/provenance
   during C02.3 if required for replay, rather than fetching a new live page.
2. Drive `run_screener_company_worker` with its fixed `now_utc`, worker identity
   and fake `host_client`. Keep the production `scrape_screener_company_path`
   implementation. Supply `LAURUSLABS_standalone.html`, matching standalone peers
   and quick ratios, using the existing response construction patterns in
   `test_screener_vertical`. Declare any warehouse-ID/period/link substitutions as
   synthetic derivatives; verify parser acceptance before treating them as valid.
3. At T0 accept the new version, with one immediately published presentation and
   one expected but missing transcript. Verify original bytes/raw cells, source
   lineage, standalone scope, accepted version and expectations. Let production
   acceptance/promotion/enqueue owners create follow-up work; do not seed a second
   acceptance/document implementation. Recording links remain metadata unless
   their current explicit allowlist permits a download.
4. At T1 replay a controlled financial revision through the same worker/path.
   Preserve the first version and acceptance/supersession history. Reuse the
   pattern in `test_new_accepted_parse_supersedes_without_losing_history`; freeze
   the exact changed financial cell and expected delta in the fixture manifest.
   Replaying identical bytes must remain idempotent without losing fetch history.
5. At T2 call `reconcile_artifacts(due=True, ...)` with real
   `PersistedArtifactAdapter` and fixed clock. Inject `source_refresher` only to
   call real `scrape_screener_company_path(document_only=True,
   expected_company_id=..., expected_result_period=...)` with fake transport and
   isolated paths. A callback that merely manufactures success is insufficient.
   Group due documents to verify one bounded source refresh per issuer/event.
6. At T3 return a declared synthetic version of the same company page containing
   the late transcript link. The existing document-only path must promote it
   under the same issuer/period and preserve the accepted financial version,
   financial rows and acceptance history exactly across T2/T3. Distinguish the
   new document parse/fetch/link observations from unchanged financial acceptance.
7. Run `run_document_download_worker` with deterministic session/clock/sleep,
   explicit eligible scope/type and an isolated store sentinel/capacity fixture.
   Use existing native-text/PPT fixtures and preserve hash/media/attempt/source
   evidence. Exercise real store validation; do not broadly disable it.
8. Call `extract_document` with the existing deterministic FakeOcr/NoOcr pattern
   and fixed clock, then reconcile readiness through the real persisted adapter.
   Verify one logical artifact, immutable original content, extraction cache
   identity and pages/segments; downloaded bytes alone are not usable extraction.

Existing anchors: `test_screener_vertical` acceptance/revision/standalone tests;
`test_screener_discovery` scope, idempotency and worker fixtures;
`test_credit_rating_acquisition` accepted-link promotion/enqueue;
`test_d09_artifact_reconciliation` due source grouping, fake-clock progression,
absence states and bounded retries; `test_d02_document_downloader`;
`test_d03_document_extraction` cache/page/origin checks.

Pass requires financial acceptance with optional absence, honest
not-issued/not-yet-issued/unknown/unavailable/blocked states, exact issuer/event,
late-link promotion, immutable content and validated extraction. Existing D09
fixtures alone do not prove this complete flow: some callbacks inject already
ingested content rather than performing the whole delayed production refresh.

## Flow B — failed URL and distinct recovery strategies

Begin each parameter case from the same expected logical artifact and stale URL.
Use the actual generic queue worker with fake HTTP 404/403/HTML-as-PDF responses,
then verify failed download attempt/source evidence with no accepted content.
Do not collapse technical failure, source unavailability and blocked access.

Parameter cases:

- **Requeue/replacement:** reuse `document_download_recovery.requeue_document_downloads`
  and `register_replacement_document_url`; preserve old source/action evidence,
  queue the selected replacement and run the canonical worker. A URL registration
  is not successful content recovery until the validated file is persisted.
- **Alternate official source:** run `alternate_source_recovery.run_document_recovery_worker`
  with an explicit BSE, NSE or issuer-IR source and fake fetcher. Reuse the DA06
  JSON and inline adapter responses; retain returned issuer/date/event evidence,
  candidate selection/attachment and blocked-publisher policy. The canonical
  worker downloads the selected allowed candidate into the same artifact.
- **Browser-provided bytes:** reuse the browser command's `validate_report` and
  canonical `import_report`/finish persistence, with a seeded isolated browser job
  tied to the artifact and synthetic capture/response evidence. Supply the
  authorized finite run and fake browser transport; never launch a live browser
  or visit a publisher. Do not download supplied bytes a second time. Retain
  original HTML/PDF and generated derivatives with distinct origins.
- **Saved rejected-page repair:** invoke the real
  `commands.recover_quarter_document_links.main` with `--apply` against only the
  disposable DB. Its `candidates` query requires the verified eligible issuer,
  an accepted standalone quarter, and a rejected parse whose only blocking error
  is manifest coverage. Its production
  `enqueue_concall_documents_for_accepted_parse` call promotes independently
  verified links. Freeze matching rejected Screener bytes; links may be repaired
  while financial observations and acceptance remain rejected. The complete seam
  is not yet proven as an H05 test. Manual import is a separate operator case using the existing
  `import_manual_document` path, signature validation and audited action.

For every successful case compare the pre/post artifact ID, issuer/event/type,
original/replacement source IDs/URLs, immutable content hash/path, attempts,
recovery actions and reconciled queue/readiness state. Repeat the same case to
check idempotent artifact/content outcomes while retaining legitimate attempt
history. Verify extraction when readiness requires it, not merely a success flag.

Negative cases retain wrong issuer, wrong period/agency, ambiguous candidates,
publisher unavailable, policy-blocked redirect and technical failure as distinct
outcomes. Use `test_da06_recovery_matching`, `test_da06_recovery_attachment` and
`test_browser_rating_recovery` patterns. Browser issuer validation tests do not
prove exact-event correctness; record unsupported period checks as gaps requiring
separate behavior work, rather than inventing a passing assertion. Synthetic
signature-only `%PDF` bytes in attachment tests are not a valid extraction fixture;
use a proper existing PDF for the successful download/extraction case.

## Provider inventory and bounded gaps before implementation

The hashed inventory covers canonical `scrapper/tests/fixtures` and `golden`.
Copied A2/B1/B2 trees and live acquisition corpus are not canonical fixture proof;
their preservation/classification remains C03. Inline test responses are indexed
as test cases and must be explicitly frozen if used as the replay corpus.

- Screener: standalone/consolidated, peers, quick ratios and P02 HTML exist.
  The result screen is currently generated inline. Missing fields/identity/scope
  cases use test transformations. Freeze exact initial/revised/late variants.
- BSE/NSE: D01 BSE HTML and DA06 live-shape-named JSON exist, plus inline adapters
  for identity/event/attachment/redirect handling. Names and original URLs do not
  establish acquisition permission, capture dates or unchanged live schemas.
- Issuer IR: D01 company IR HTML exists; bounded same-host discovery/blocked-link
  behavior is inline in DA06 adapter tests. Freeze chosen responses and dates.
- CARE: a generator explicitly creates a synthetic CARE-style D04 PDF. D01 rating
  HTML is fixture evidence; links in Screener/manifest files are not report bytes.
- CRISIL, ICRA and India Ratings: rating links and inline resolver/browser/policy
  tests exist, but no separately authenticated agency response corpus covering
  every normal/error/issuer/event variant is established by this inventory.
  Use declared synthetic offline cases for H05; do not claim captured provenance.
- Generic downloads: existing D02 tests cover 404/403, diagnostic HTML-as-PDF,
  redirect/blocked host, duplicate bytes, limits and storage failure. These are
  generic transport cases, not evidence of each publisher's actual response.
- Extraction: generator-backed D03 PDFs/PPT/images, D04 CARE-style PDF and D05
  transcript plus malformed/media fixtures exist. Keep originals distinct from
  OCR/generated outputs. Native/OCR engine/options versions must be explicit.
- Other current providers: Trendlyne, AMC workbooks and MFData are included in
  the inventory and retained. Their full flow/cutoff checks expand at C27; absence
  from H05 A/B is not permission to retire them.

Before C02.3 passes, explicitly cover normal, missing/changed fields, 404/403,
HTML-as-PDF, wrong issuer/quarter, duplicates and redirects for each touched
provider where applicable. List inapplicable cases with reasons. No live fixture
acquisition is authorized here. The complete flows must run at baseline, before
C04/dependent extraction and after relevant C11–C23 changes; C27 reconfirms and
extends them. A component-suite pass is not an H05 pass.
