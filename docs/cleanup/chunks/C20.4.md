The shared Screener transport is opt-in through `shared_permits=True`. Existing defaults, public command entry points, CLI/Compose roles, queue tables, status values, and legacy `ScreenerHostClient` behavior remain unchanged. The daemon/company worker, result discovery, delayed document reconciler, and collection-scope monitor can now receive one explicit shared client factory. Shared mode refuses construction unless Linux, migration 071, and a valid Screener session cookie are present; it never migrates, authorizes, or falls back to unmetered requests.

Each company, expectation, and collection-scope claim is renewed while the shared transport is waiting or streaming. A pre-dispatch administrative host wait releases the claim to its existing retry schedule without incrementing the queue/check attempt and without writing a fetch, check, run, or scope observation. After dispatch, the attempt remains spent. Partial Screener responses are stored as `shared_partial` evidence before a deferred company claim is released. Reconciliation and monitor defers preserve availability/eligibility and failure history. Stale claim tokens and expired leases raise `OwnershipLost` before persistence, so another worker cannot be completed by an old caller.

Every Screener company, peer, quick-ratio, commentary, result-screen, and manually followed redirect request obtains its own fenced `screener` publisher permit. Cookie values stay in the session jar; foreign-host redirects are rejected before a request. Existing publisher-group cooldown, Retry-After, circuit, alias, and unrelated-host behavior is inherited from C20.1–C20.3. No database write transaction spans HTTP I/O. The shared transport remains behind `operations/workers`; source/workflow code receives it by injection.
