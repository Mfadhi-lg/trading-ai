# Document evidence/readiness interface — C25.3

Consumers import `document_evidence` from `scrapper.research.features.documents` and supply a caller-owned read-only SQLite connection, an explicit positive `expectation_id` and an offset-aware `as_of_utc`. The interface reads existing D09 check events through `db.documents.evidence` and canonical document readiness; research has no SQL, source parser or acquisition workflow dependency. No worker, migration or acquisition consumer changes. Legacy readiness adapters/imports and commands remain unchanged.

`document-evidence-v1` returns company/event/period/type identity, event evidence/source, expectation creation and event observation times, check ID, source/URL, recorded `ArtifactCheckResult`, exact evidence/error JSON, check observation time and the requested cutoff. Evidence retains original content/version/hash/origin, acceptance/extraction references, units and nulls when the producer recorded them; missing references remain missing. The interface does not manufacture content hashes, extraction text or ratings, convert units or attest that stored bytes prove issuer/event correctness. Official versus machine/generated origins remain in the producer evidence. `available_at_utc` is the selected available check time, not publication time, nor reconstructed initial acceptance time.

The latest eligible recorded check is selected by normalized UTC observation time, then check ID. Expectation creation and event observation must precede the cutoff; earlier requests raise KeyError, as do unknown expectations. Offset-aware timestamps are required. Later checks never replace earlier cutoff evidence; today's expectation availability, current normalization, latest extraction and provider publication dates are never used as historic readiness. Inconsistent check times preceding the expectation/event fail closed.

An expectation without a recorded check at the cutoff has NULL result/check/time; this is not a negative, unavailable or not-issued label. All nine D09 availability states are retained without collapsing inaccessible/discovery_failed/unknown/not_applicable/source_not_covered into zero. `recorded_ready` is True only for a recorded available result, otherwise NULL. Retryable/error details remain evidence rather than scheduling instructions. Missing/optional documents do not invalidate accepted finances. No labels, eligibility or Focus decisions are derived here.

Limits: D09 check timestamps are operator/producer supplied observations; the existing table has no independent transaction ingestion timestamp or immutable content snapshot per check. This projection is recorded-as-of replay, not certified historical PIT availability. It cannot prove that backfilled checks were present historically, fill gaps in old evidence, or reconstruct subsequently edited identity/event rows. Such consumers need separately reviewed ingestion/provenance evidence; they must not advertise this contract as historical PIT-safe. The interface deliberately does not infer past acceptance from a current artifact. B1 capture guarantees and B2 audit-only disposition are unchanged.

Rollback omits the five C25.3 additions; no schema/data restore or queue handling is required. C25.4 reserves future domain contracts separately. No training, LLM/provider integration or trading is implemented.
